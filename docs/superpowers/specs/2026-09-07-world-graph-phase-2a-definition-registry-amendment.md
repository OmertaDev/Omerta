## Stable compiler boundary

`namespace` and intrinsic `packageId` are exactly verified `bundle.package.id`; owned logical IDs are exactly `packageId::localId`. Versions are positive JS safe integers, persisted as checked BIGINT and returned as checked Numbers; no semver/text ordering. `compilerVersion` remains the compiler's bounded text token. Artifact format and IR versions are numeric 1.

The trusted descriptor has exactly five own data keys: `{packageId, packageVersion, authorityProfile, bundleHash, dependencyLockHash}`. It comes from trusted build configuration/index, separately from uploaded bytes. Select those five fields from the build-index row; `file` and `publicManifestHash` are not descriptor keys. Reject extras, missing keys, accessors, arrays, invalid scalars, and inherited authority. Audit operator IDs are nonempty trimmed strings of at most 200 characters, with no controls; they do not establish identity or permission.

At every public entry, inspect exact own data properties and synchronously snapshot all request primitives before the first await (including transaction/gate acquisition). Admit bytes only as a bounded owned copy of string UTF-8 bytes or a genuine fixed, nonshared Uint8Array/Buffer view; use intrinsic typed-array accessors to inspect bounds, reject accessor-spoofed, shared, resizable, detached, or otherwise unsafe views, and copy only the exact view range. Bound string UTF-8 size before allocating the copy. Do not reread caller objects or mutable bytes after admission. Verification, persistence, and replay comparison all use the same private copied bytes and descriptor. This follows the structural admission discipline of the existing publisher without importing filesystem tooling into runtime. Other request/policy arrays and primitives are copied/validated before awaits too.

Task 3 calls the existing verifier without changing its interface:

  authorityProfile,

Compare verified `bundle.package.id/version` to the trusted descriptor; disagreement is `content_artifact_conflict`. Never trust bytes to choose their authority profile. Retain all seven hash domains unchanged. Definition commitments come from owned `bundle.ir.nodes` with `nodeClass === 'definition'`, in emitted order, with one-to-one matches in `canonicalHashInputs.definitionById` and `hashes.definitionHashById`. Imports create no intrinsic row or local membership. Membership ordinal is the zero-based index in this filtered ordered list, not the ordinal of an arbitrary IR node.

Initial ingestion parses the supplied bytes only for bounded exact dependency lookup hints. Use `parseAuthoredJson` with the verifier's 64 MiB artifact, depth 64, string 64 KiB, 100,000 object-member, and 100,000 array-item limits before database fan-out. Resolve an iterative visited-hash closure from exact stored artifacts, never active pointers, source paths, caller catalogs, or network fetches. Validate hint key/scalar forms before lookup. Detect cycles and conflicting package-version/hash entries. Before admitting each new row, enforce the published `PHASE2_LIMITS` closure ceilings (2,048 catalog bundles, 64 MiB catalog bytes, 100,000 nodes, 500,000 edges, 1,000,000 references); use checked accumulation and keep root plus closure within the verifier's effective-resource limits, including 2,048 packages. Traverse at most the package ceiling; no recursion on authored depth. Read dependency `dependencyLockHash` and authority from its immutable trusted row, verify dependencies bottom-up, and pass each verifier exactly its own deduplicated transitive closure, excluding itself. The root receives exactly its closure, not the entire registry. Bound database reads to unique dependency hashes; shared DAG edges must not cause repeated row fetches. Preserve compiler failure codes, including `content_dependency_unresolved`, `content_dependency_drift`, and `content_input_limit`.

## Public interfaces and lifecycle

```ts
type StoredArtifact = {
  namespace: string; bundleVersion: number;
  authorityProfile: 'production' | 'fixture';
  bundleHash: string; dependencyLockHash: string;
  definitionCount: number; replayed: boolean;
};
storeSealedBundle(pool, { canonicalBytes, expectedIdentity, operatorId }): Promise<StoredArtifact>;
registerItemDefinitions(pool, { bundleHash }): Promise<{
  bundleHash: string; definitionCount: number; replayed: true;
}>;
createActivationPolicy({ environment, allowedProfiles }): ActivationPolicy;
activateStoredBundle(pool, {
  namespace, bundleHash, expectedRevision, expectedPreviousBundleHash, operatorId
}, activationPolicy): Promise<{
  namespace: string; bundleHash: string; dependencyLockHash: string;
  activationRevision: number; eventId: string; replayed: boolean;
}>;
definitionByHash(queryable, definitionHash): Promise<ItemDefinition>;
activeDefinition(queryable, logicalItemId): Promise<SelectedDefinition | null>;
runLedgerInvariants(pool, { alert = true, activationPolicy = null } = {});
```

Request objects are closed; an activation call cannot include source, parsed bundle, environment, profile, definitions, dependency catalog, or policy overrides. Public mutation-shaped operations require a pool with `connect`, own one checked-out client and transaction, and reject nested public entry. `registerItemDefinitions` is verification/replay only, performs no DML, and cannot fill missing memberships. There is no public `activateItemDefinitions` or independently committing definition-registration operation.

A successful store means complete registration, including a valid zero-definition artifact. Within its transaction, insert the namespace's revision-zero placeholder if absent, lock/re-read it, verify bytes and exact dependencies, inspect immutable conflicts, register definitions and memberships, and commit all rows together. Placeholder insertion is not activation. Do not rely on pg-mem conflict-ignore row counts to identify new rows; read authoritative existence under the gate/lock. Store exact byte sequences; do not normalize and accept different byte representations. An existing artifact may replay only when bytes, all immutable projected metadata, intrinsic rows, and complete membership set agree. Audit `registered_by/at` retain the original registration on replay. A corrupted/incomplete existing registration fails closed and is never repaired by store or register.

Definition version rules, checked after the namespace lock:

- Existing exact logical ID/version/hash/canonical bytes may gain a new bundle membership even when newer intrinsic versions already exist.
- Same ID/version with different semantics/hash is `item_definition_conflict`; same hash with mismatched canonical projection is corruption/conflict, never replay.
- Only a previously unregistered version lower than the greatest registered version for that logical ID is forbidden (`item_definition_conflict`). Numeric versions may skip forward.
- Exact artifact replay and exact intrinsic reuse never modify old rows. Package versions need not be registered in numeric order; their identity remains unique per namespace/version.

`ItemDefinition` is a safe intrinsic projection: `logicalItemId`, numeric `definitionVersion`, `definitionHash`, `packageId`, `kind`, and any present `family`, `tags`, `rarity`, `stackable`, `tradePolicy`, `ownerScopes`, `qualityMode`, `maximumLotQuantity`, `conservationClass`, `metadata`, plus nullable `tradePolicyHash`. Preserve omission versus explicit empty arrays; return no arbitrary `bundleHash`, canonical preimage, private source, or internal hashes. `tradePolicyHash` is exactly `definitionHash` when policy exists, otherwise null; it is not a reusable standalone policy hash. Return detached/frozen safe values. `definitionByHash` verifies canonical preimage/hash/projection and throws `definition_not_found` only for absence. `SelectedDefinition` adds `bundleHash`, `namespace`, `activationRevision`, `eventId`; absence is null only when the selection row is absent. Broken required version/membership/event/pointer joins fail `definition_inactive`. Private containing-bundle lookup must prove exact membership, never choose an arbitrary bundle.

## Policy, selection, and replay

Policy is frozen and branded using module-owned identity; a plain clone, serialization round trip, or forged property cannot authorize selection. Factory takes exactly `environment` and `allowedProfiles`; environment matches `^[a-z][a-z0-9_-]{0,63}$`, profiles are a duplicate-free explicit subset of `['phase2_economy']`, including empty for deny-all. Freeze the sorted copied allowlist. Environment is trusted operator audit context, never artifact identity. The separately passed branded policy is authoritative for its environment; no second implicit environment is inferred from bytes or process variables.

Both production libraries and experiences are eligible when their profile is allowed and complete registration verifies. `activatable` retains its legacy experience meaning and does not disqualify a library. Fixtures are never selectable. Invalid brand/config is `content_activation_policy_invalid`; valid policy denying an artifact is `content_activation_policy_denied`. A read-only internal assertion/snapshot interface lets invariants inspect current branded policy. Validate historical snapshots structurally/canonically and against the target event's artifact; do not pretend the serialized historical snapshot has the live module brand.

Under the namespace lock, verify target stored bytes, trusted metadata, dependency closure, complete membership, namespace ownership, and current policy before returning even a replay. Let current pair be `(revision,hash)`, or `(0,null)` for the placeholder:

- Target differs: expected pair must equal current pair; otherwise `content_activation_conflict`.
- Target equals current hash: exact current expected pair is no-op replay; no new event or metadata rewrite.
- Target equals current hash and current revision is expected revision + 1: ambiguous-commit retry replays only if the current event's previous hash equals `expectedPreviousBundleHash`. It must be the event referenced by the current pointer, not any historical match.
- Every other same-target stale request conflicts, including ABA. `operatorId` is audit metadata; it does not change the defined replay identity or overwrite the winning operator.

Validate expected revision as safe integer >=0; expected previous hash is null exactly when expected revision is 0. Invalid pairs or a requested namespace different from the target artifact's namespace are `bad_content_request`; a well-formed pair that does not satisfy CAS is `content_activation_conflict`. Reject a real transition past MAX_SAFE revision as `content_activation_conflict` while still permitting exact no-op replay at the maximum. A real selection increments namespace revision, appends the event with exact previous/target hashes, compiler/IR/version/profile/report metadata and canonical policy snapshot, replaces the full namespace selection set (deleting absent definitions), then updates the namespace pointer last. Event, selections, and pointer commit together. Explicit R2-to-R1 selection is allowed after fresh policy/membership verification and correct CAS. Empty bundles clear all namespace selections and still record a real event. Exact old intrinsic reads remain valid; Task 3 does not invent a later Phase 2 job recovery test.

## Transactions, reads, failure, and recovery

Use a separate module-owned AsyncLocalStorage/WeakMap transaction brand for Phase 2. Do not reuse item transaction guards or expose undo handles to authored content. Same-namespace store/version checks and activation serialize on the placeholder row; dependencies are immutable reads, so do not acquire dependency namespace locks. PostgreSQL owns rollback/MVCC. Never run application compensation on PostgreSQL; initialize `dbCaps` through approved real-backend setup before testing raw pools.

pg-mem uses one module-global serialization gate shared by mutations and the **entire** multi-query public read/invariant callback, regardless of pool/proxy/forwarding aliases. An active matching internal context bypasses reacquisition to avoid deadlock. A one-time tail wait is insufficient. Hold the gate through rollback compensation and until a result or final rejection is determined. Record inverse operations before every possibly successful write, restoring/deleting only rows this operation changed. Store undo removes memberships, new intrinsic rows, artifact, and its newly created placeholder in FK-safe order. Activation undo restores the old pointer, removes new selections, restores prior selections, removes its event, and removes a newly created placeholder. Never overwrite pre-existing audit rows or delete reused intrinsic versions. Failure after COMMIT acknowledgement is not simulated as a rollback failure; a lost acknowledgement is recovered by exact replay.

Use `withPhase2Read(queryable, callback)` as the common pg-mem whole-callback gate. Public pool-based multi-query reads own a PostgreSQL repeatable-read/read-only snapshot; reads given an already checked-out client participate in the caller's snapshot rather than nesting transactions. The invariant wrapper owns its existing PostgreSQL repeatable-read snapshot and wraps its collection callback in the Phase 2 gate; alert delivery occurs afterward. Select the backend path using established `dbCaps`, not by swallowing PostgreSQL errors: replace the broad BEGIN fallback in `src/invariants.js`. A real-PostgreSQL snapshot-start failure releases/rolls back its client and propagates failure; it must execute zero invariant collection queries and must never use the pool for an unsnapshotted fallback. pg-mem takes its known gated path directly. Selection resolution must use a single exact membership/event/pointer join, so caller-owned write transactions at READ COMMITTED cannot splice separate selection generations. Immutable-row verification may follow that join; the immutable rows cannot legitimately change.

After a failed mutation, rollback/release precede stable SQLSTATE mapping. `40001`, `40P01`, `55P03` map to retryable `contention`; `57014` maps to `contention` only for a statement canceled inside this owned boundary with rollback confirmed. No implicit retry loop: callers retry the same logical store or same CAS observation, then refresh only after a true conflict. Named `23505` on artifact identity or definition ID/version is re-read/compared under a fresh transaction after rollback (or avoided using conflict-ignore plus locked reads); classify exact replay versus `content_artifact_conflict` (same hash incompatible bytes/metadata), `content_bundle_version_conflict`, or `item_definition_conflict`. Never catch `23505` and continue inside an aborted PostgreSQL transaction. Other `23505`, `23503`, `23514`, `23502`, and `25P02` are integrity/programming failures (`content_registry_corrupt`), not contention or replay. Input failures before SQL use `bad_content_request`; missing root artifact uses `content_artifact_not_found`; stored root projection/membership corruption uses `content_registry_corrupt`; dependent verification drift retains `content_dependency_drift`.

Transport failure at COMMIT or unconfirmed rollback is `content_commit_unknown`, not a claim of rollback. Release/discard the broken PostgreSQL client; reconcile through a new connection by retrying the exact request. Store exact replay and CAS predecessor replay make committed outcomes recoverable. If pg-mem compensation fails, reject `content_registry_recovery_required`, retain sanitized original and compensation diagnostics for operators, and poison the module's Phase 2 gate so later calls fail closed instead of exposing partial state. Test harness recovery recreates its disposable database/process; no public repair method. Logs/results never include artifact bytes, private inputs, raw SQL, connection strings, or policy secrets. Success/replay observability occurs only after transaction completion.
