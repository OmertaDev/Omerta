## Resolved findings

- **P3-VIS-01, high, corrected before projection work.** Family graph references inherited legacy Crew visibility. A Crew newcomer outside the Family could receive a private operation reference/status. The corrective checkpoint separates modes and tests current Family, historical participant and cross-Family Crew cases on both databases.
- **P3-HINT-01, medium, corrected.** Initial operation hint audiences repeated the same Crew/Family mismatch and omitted former commitment owners. Family hints now target the current Family, opener, role owners and historical promise owners. Private discovery/generic actions target only their actor; grant revocation includes the revoked audience. Hints carry no identifiers or domain state. Native and mounted-socket tests exercise durable-event validation and stale membership.
- **P3-RECIPE-01, medium, corrected.** A valid public recipe referencing an administrator-seeded hidden material disclosed that material ID through its consumes list. The public recipe adapter now omits recipes with hidden input or output definitions before planning or serializing them. Current pilot definitions remain public. Both hidden-input and hidden-output regressions are included in the aggregate lane.
- **P3-FAMILY-01, medium, corrected.** Selecting an authorized historical operation from a former Family could replace the current Family context used for the catalog. Catalog/list authority now follows current character membership and Crew affiliation; selected-operation read/action authority remains independent, within the same snapshot.
- **P3-CLIENT-01, medium, corrected.** A queued or in-flight old-session response could reach general action UI after replacement; an old world command could remain queued across character replacement. The API queue checks its session before and after fetch; world commands also bind the captured character/epoch. Replacement clears obsolete busy/retry state. VM tests execute the actual production coordinator and API functions.
- **P3-HTTP-01, functional, corrected.** Fastify's nonempty parsed query object has a custom prototype, rejected by the internal closed-object contract. The route now copies only its validated `operationId` into a plain record. Extra/duplicate/coerced query fields still fail. Mounted API tests cover selection and hidden/nonexistent response equivalence.
