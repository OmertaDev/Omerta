# N14 exact canonical adapter proposal

Base `406f5a8d0c10bd3280b52f411015747defc5e6f2`. This is a component proposal,
not installed canonical recipe authority, completed gameplay, or release evidence.

Initial supported cargo is exactly one active account-title standard precision
tool with canonical recipe:precision_lock_tool creation. Current title may have
passed to a legitimate customer/purchaser. Immutable maker identity is verified
internally and never disclosed. Award/import/salvage/unknown origins and tempered
tools remain unsupported. No requirement or assumption that title returns to its
maker; no rental, consignment, storage, operation escrow or character-title item
can qualify. A current open Foundry Depot is owned by the caller's one living
original character, who is physically in that same district. No enrollment,
prepaid cash, foreign counterpart or estate liability
is created. Later heirs can only create a NEW request under their genuine current
business/title/source; an old receipt is historical acknowledgment only.

The proposed authored package consumes one precision UID and returns one standard
salvage part. Its manufacturing source consumed one hardened steel and two
salvage parts. Exact input events and completed immutable recipe guard must agree.
Recovery thus loses one steel and one part per craft/recover cycle. Condition is
0–20 out of100 inclusive; repair restores condition but never increases this
fixed yield. No steel, game cash, XP, equipment, quality bonus or artificial
demand is created. Healthy and tempered tools cannot use a fallback recipe.

## Coordinator-owned canonical source seam

Do not implement this as a new public grantStack wrapper. Install the authored
package into the real reviewed Phase1 registry/manifest/policy/census. Canonical
Craft must export only the closed leaf:

`recoverWorldGraphEquipment(client,{accountId},terms,canonicalRequestKey)`.

That leaf must use ONLY DEFAULT_CRAFTING_CONTEXT and the fixed recovery recipe.
Use real withItemMutation/actorContext/account mutex; enforce ordinary current
craft discovery/location/level/skill/freeze and account admission. Preserve any
current shared production/reservation guard semantics; do not invent an operator
permission or bypass a configured restriction. Request authority binds the actual
recipe identity AND exact originalCharacterId/businessId/itemId/sourceHash.
Historical canonical replay precedes fresh actor/title eligibility.

Inside the real canonical mutation: actor→account→owned Depot→exact UID→condition,
call lockEquipmentRecoverySource (which only checks facts, grants no mutation
authority), enforce zero canonical cash cost and fixed closed recipe shape, then
consume EXACT terms.itemId through existing consumeItem. Produce outputs only via
the existing produceRecipeOutputs on the authored recipe with the SAME mutation
token. Return kind:equipment_recovery, actual recipe/source/body identities,
cashCost0, canonical inputs and outputs. Revalidate current source/condition
after any relevant wait before consuming. Item and source locks remain held.

The generic craftWorldGraphRecipe entry MUST reject this exact recipe before
effects and direct it to the dedicated leaf. Existing generic uniqueInput chooses
the oldest owned UID and has no worn/source gate: merely adding a recipe would
permit the wrong UID or healthy/unknown-origin inputs. All aliases/manual/direct
callers must encounter the same rule; no optional caller hook or key prefix is
authority. Existing consumeItem+grantStack events are used, no new event enum.

The N14 module validates the actual two events under the canonical mutation key,
the original UID consumed state and exact account output. It never calls any
grant function. One receipt row per UID prevents independent duplicate recovery.
No caller-supplied adapter, deployment flag or fabricated G context exists.
