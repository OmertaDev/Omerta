# Bounded Family CASH/AMMO custody

`tools/rc1-family-cash-ammo-journal.js` reconciles complete committed snapshots with exact decimal strings and authoritative canonical outcomes. It classifies formation's personal cash sink, personal cash tribute to one identified Family, car melt's personal ammo plus Family cash/ammo creation, and last-member dissolution's cash/ammo destruction. Membership, rank and leadership changes alone create no resource flow. Per-character cash+bank and ammo ledger parity retain the other endpoints; unrelated personal receipt semantics remain outside this journal.

The source-authored paths have no generic personal treasury withdrawal or personal ammo-bank deposit/withdrawal endpoint. The Family ammo bank receives melt tithe and is destroyed at dissolution. Other Family spending/income, war, turf, contracts and territory remain unsupported; OMR/reserve reconciliation belongs to a separate journal. An unsupported receipt produces `PARTIAL_UNSUPPORTED`, and unexplained balance movement fails. There is no residual adjustment or floating-point tolerance.

The adapter accepts `snapshotFamilyCashAmmo(pool)` or complete retained native `tables` snapshots. `reconcileFamilyCashAmmo(before, after, {operations, familyIds})` requires the actual POST account/character, request identity and canonical response; it never accepts a replay as new movement. A character crossing multiple Families requires finer committed boundaries. It preserves all old transaction rows and checks recipient, owner, amount, sign, car disposal and Family endpoints. Every native boundary retains the complete before/after custody input. The shared global observer remains unchanged and its unknown classifications remain visible.

Run `node test/rc1-family-cash-ammo-journal.js` for lifecycle and corruption controls. Run `node test/rc1-family-cash-ammo-native.js --postgres` with `COORDINATION_TEST_DATABASE_URL` pointing to the disposable local control database and `RC1_FAMILY_CUSTODY_OUTPUT` naming a fresh restricted directory. A clean immutable commit is mandatory. The proof creates two ordinary accounts/characters, declares only founder level75 respect eligibility before baseline, and uses the actual daily check-in to fund formation. No direct balance, item, status or membership grants occur. Measured formation, nonzero tribute, natural GTA acquisition, melt, succession and dissolution use canonical APIs. One scoped late ammo-ledger fault must roll back completely before the exact request is retried. Original worker callbacks accompany any public cooldown waits.

`test/rc1-family-cash-ammo-retained.js` accepts `RC1_RETAINED_ROOT` and fresh `RC1_FAMILY_REUSE_OUTPUT`. It verifies sealed artifact hashes before independently reclassifying the original-lifetime Family D window from `7df52b3f` and the two social windows from `5227fe19`. Historical intermediate equations do not substitute for missing complete snapshots: this audit covers the retained initial/final windows only. Legacy request payloads were overwritten by response bodies and are explicitly unavailable. Invocation/completion order is not database commit order. A historical audit is not a fresh-source native pass, and no existing evidence is rewritten.

This component does not clear the full resource taxonomy, matrix, 90-day workloads or production release gates. Native and historical execution results are documented separately after sealing.
