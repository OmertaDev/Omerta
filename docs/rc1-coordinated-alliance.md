# Bounded coordinated-alliance component

`tools/rc1-alliance-policy.js` selects canonical diplomacy and Knowledge actions from the acting account's ordinary authorized projections. It records seeded selection, exact request keys, current instance action/revision, opaque account target and ACL revision. A pending request survives checkpoint/restore unchanged; lost-response recovery cannot select another action. Unknown completed replays are retained and block further selection. Known replays must match the original receipt apart from the authored replay flag.

The supported alliance consists of three actual Families linked by three bilateral pacts and three independent investigators deliberately sharing evidence. Pacts are social relationships; they confer no Knowledge visibility. Cross-Family cooperation uses explicit owner-to-account grants issued by the character-name target lookup. Family operations require a uniform Crew within one Family, so cross-Family operation execution is excluded. No alliance-wide permission or new gameplay is invented.

The native proof creates four ordinary accounts/characters. Three founders receive only a declared prebaseline level75 respect fixture, collect an actual check-in and pay the actual formation cost. The fourth account remains an ordinary outsider. No direct cash, ammo, item, membership, deadline or status grants occur. Measured canonical pacts, travel and discovery produce docks/foundry/docks claims. All three investigators contribute their own original claim through explicit sharing, and each completes the existing no-reward Split Ledger conclusion.

Controls verify that pacts alone grant no visibility, outsiders cannot read or act in another account's instance, recipients cannot reshare, stale ACL revisions fail, and revocation hides archived/shared references and rejects a previously issued action. Regrant permits completion. Exact share, archived-reference and conclusion retries preserve the full canonical state. All policy selections receive only their actor's views; independent snapshots and invariant reports never feed choices.

Run `node test/rc1-alliance-policy.js` for policy controls. For a fresh native proof run `node test/rc1-alliance-native.js --postgres` with `COORDINATION_TEST_DATABASE_URL` targeting the disposable local control database and `RC1_ALLIANCE_OUTPUT` pointing to a new restricted evidence directory. Source must be clean and unchanged through sealing. Full canonical invariants, the unchanged shared resource observer and the separate exact Family CASH/AMMO journal observe boundaries. Unknown resource classifications remain explicit. Original workers boot, but this scenario advances no logical time and claims no pact-expiry or recurring-worker coverage.

Implementation ancestry is root `9e05bf089fff68ba6c65b805ac6b1c5c33c26c24` plus exact existing CASH/AMMO journal dependencies (original commits `0c0f134b`, `9cef58c3`, `dfbd7923`; local cherry-picks `0bd4723d`, `f9efd563`, `748a9c7e`). Only the new alliance files need integration after those dependencies. No runtime, shared observer, package or workflow files change.

The component does not qualify 25 actors, 90 days, three seeds, 225 matrix runs, production, anti-hegemon coalitions, warfare, operation capital/items, OMR reserves or the full resource taxonomy.
