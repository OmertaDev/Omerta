# Funded external work: unavailable provenance and activation boundary

Base `b0cf6767a7cd74a06dfdd8a1afbd0ccb7b6414f1`. Existing `resourcepayments` verifies Stripe funding into USD-micro resource treasuries; `resourcework` allocates those resource balances. Neither Stripe receipts, resource-ledger test/live balances, game cash, OMR, F11 wages nor F17/F24 consent is ETH/USDC/HOOD backing. All legacy payment, provider, work and recovery records remain untouched. `stockcatalogv2` verifies a finalized registry observation, not a work-escrow deposit. Market contracts include commitment/turf/fee settlement; none of the inspected boundaries establishes the required external-work deposit, original depositor consent, one-work allocation and original-wallet recovery proof. No repository seam is sufficiently bound to activate this feature.

Public registration is hard unavailable before any game transaction, verifier call, provider or financial side effect. Environment flags and caller-provided booleans cannot activate it. ETH/USDC funding and canonical HOOD StockToken funding are all unavailable; HOOD remains unavailable until its exact canonical finalized registry/token binding is verified. No actual network calls, signing keys, wallets, payment adapters, compute purchase, customer message or new provider dependency are introduced. A synthetic internal verifier tests controls only and never proves real backing or payment.

One bounded future market supports an original owner-funded job for one original worker, exact native/token atom amount and one typed `worker_training_session` outcome. Original owner consent binds original account/character, owned business/course, exact chain/asset/contract/deposit identity, amount, typed outcome, deadline and immutable work hash. A fresh original worker separately accepts the exact work hash; acceptance is not an external spending grant. Allocation requires the actual matching F11 session, original worker/owner/course, ordinal/stat, positive canonical stat change, energy use and exact canonical game-cash wage journal. That is gameplay proof only: wages or a completed session never create crypto funding.

Required activation evidence and trusted registrar contract must bind:

- One explicit chain identity and reviewed escrow contract address/code hash/version; finalized block number/hash, deposit transaction hash/log index, canonical event and exact asset address/decimals.
- ETH as exact native escrow, USDC as independently verified exact token deployment, and HOOD only through the authoritative canonical StockToken registry identity/index/ticker/token observation. A symbol, HTTP listing or caller-supplied token is insufficient.
- Original depositor wallet/account consent, original recipient authorization, immutable owner/work/outcome hash and complete **preexisting** funded amount. Missing, pending, replaced/reorged, foreign, wrong-chain, noncanonical, fractional/partial or already used proof refuses.
- One immutable chain+escrow+deposit identity reserved to one work. A reread under source locks precedes job/state writes. Allocation/recovery references actual existing canonical escrow events and exact atoms, never local synthetic credit, a successful provider call or an arbitrary caller success claim.
- Separate exact once-allocation and once-recovery receipts, preserved historical originals. Cancellation/expiry/death release only to the original depositor/canonical recovery recipient; heirs acquire no signing/spending rights. The SQL model must not pretend to send or refund assets.

The internal control registrar is deliberately restricted to `synthetic_control_only`. It verifies synthetic funding/recipient fixtures and records synthetic allocation/recovery under the same client transaction; each receipt explicitly says simulated and not real backing. Live registrar mode is refused. Production activation therefore requires a new explicit reviewed integration/pin, actual canonical contract/deposit/finality/source/allocation/recovery proofs, original external consent and keys retained outside the game component, independent conservation checks, and owner authorization to activate. This commit supplies no activation authority.

F17 commercial disputes and F24 management teams are graph release prerequisites, not crypto funding or control grants. F11 frozen source is the sole gameplay outcome dependency (`3c77384c41af1c03d2d74b02a9e7cb564319a39b`, review `1898dbee96cd9efd6b6501ccdbd43e31ef63a066`). No second F24 outcome or extra feature is added. Coordinator retains shared schema/hooks/registration/census/CI and all release/activation authority.
