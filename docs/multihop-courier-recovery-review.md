# Courier recovery correction — component/prototype phase

Source baseline: `d24d87c64d6b9678f0e76d099ac7bb72215f609b`. This proposal changes only `src/multihopcourier.js`, adds `test/multihopcourier-recovery.js`, and this review. The sealed merchant-return branch at `f932b83ce0f103a6e1d4ee760926ae4917f4437c` remains preserved. No schema, package, shared runtime, endpoint guard or financial activation changes are included.

COURIER-01 and COURIER-02 are confirmed defects from the independent d24 review. Original real-60-second JSON/log traces are retained in the durable packet. COURIER-01 counted expired unfunded offers forever, while expiration required both consents. COURIER-02 required every counterpart account active even for returning the original owner's existing reserve and UID.

Expired offered/ready sources leave admission and estate counterpart bounds only when their deposit, reserve, earnings and refunds are empty. Funded first/second legs always remain counted, including after expiry. An active enrolled original owner or actually-consented carrier can explicitly retire expired unfunded metadata, under the original source hash and locked source row. Neither a merely named carrier nor a foreign account acquires that authority. Historical rows and request receipts remain intact.

Recovery is action-bound, not a caller boolean. The separate root-owned `equipmentrentals.js` proposal binds one closed action into its existing private WeakMap capability and checks it on entry, every assertion and exit. Only cancel/expire permit inactive *nonrequesting* counterparts. Every original remains alive, non-NPC, its unique original account character and within the genuine sorted rental/death prelock. The requester must remain active. The owned execute path independently enforces the same distinction and requires the scope's returned action to match; unmodified older shared helpers fail closed. Fresh dispatch/travel/handoff/arrival retain all-active checks. Existing funding, original beneficiary, same-UID custody, canonical item mutation, expiry, replay and rollback remain authoritative.

Verification uses a disposable ignored archive of exact d24, overlaid only with the owned module/test and the off-repo shared proposal. Its real G/Items, registered server and canonical estate modules execute normally; no mock success, proxy authority, fake character or new public option is introduced. The regression uses actual `/v1/mod/ban` on the first carrier, actual fixed 60-second deadlines, no clock/TTL/backdating changes, incomplete and ready offers, source-bound private wrong-action refusals, banned requester/positive refusal, expired-history plus new-live death bounds, exact refund/custody books and late return/refund fault rollback with identical-key retry. The explicit late-fault transport proxy injects failure only; it does not supply successful authority or bypass canonical execution.
