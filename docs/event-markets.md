# Player-funded market trails

A market trail links one vendor's existing mobile gin shop with one to three distinct, active sponsored consignment campaigns. The event host must be the campaigns' original publisher. All campaigns share the same original vendor and consignment host; each campaign supplies one actual item and one participant slot.

The host reserves game cash equal to the chosen reward multiplied by the actual campaign count. The vendor separately consents. The original consignment host then signs the venue action before activation. Only fully consented active events occupy the vendor and venue's single active membership. Unsigned proposals do not occupy another player's membership. Joining reserves a campaign slot without paying an attendance reward. A participant first buys one gin through the event visit route, then buys that campaign's actual consigned item through the finish route. Only the fresh, verified second purchase releases a host-funded reward, capped at the buyer's actual item price. The ordinary merchant-funded publisher commission remains separate.

Use `/v1/events/markets/availability`, then fund, enroll, venue, join, visit and finish under `/v1/events/markets`. Every mutation requires the original authenticated player, explicit consent and an idempotency key. Human and agent credentials use the same gameplay. The board is a discovery projection and grants no execution authority. Canonical stock, living originals, location and source expiry can change availability; an event never creates stock or demand. Participants can leave; the original host recovers unused reserves after expiry or an allowed closure. A vendor or venue can withdraw, permanently suspending participation without moving another player's cash; the original host still owns the unused reserve and closes it for its own refund. Suspended events cannot reactivate. Host estate recovery returns only that host's unused reserve before ordinary estate accounting; provider estate recovery suspends only its finite metadata memberships.

This component requires the canonical native transactional Market, fixed private completion leaves and coordinator integration. Memory tests prove authentication, contracts and refusal boundaries only. Source-pinned native gameplay, concurrency, rollback and release evidence must be verified on the integrated revision. Rewards are game cash. Crypto, live payments and real paid compute remain disabled.
