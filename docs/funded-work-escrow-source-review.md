## Canonical escrow source

`OmertaWorkEscrowV2.sol` uses the repository's Solidity0.8.26/OpenZeppelin SafeERC20 and ReentrancyGuard conventions. Its constructor requires chain1 and code at the fixed USDC address. There is no owner/admin, server signer, outcome oracle, upgrade, redirect, token list, generic call or surplus sweep.

Original funder `msg.sender` escrows exact native/token atoms against immutable payee, asset, workHash, nonce and a 60–900-second deadline. Funder+nonce and funder+workHash cannot be reused. Exact incoming USDC balance delta rejects transfer-fee/partial custody. Only the original payee accepts; only the original funder explicitly allocates the full amount against a nonzero outcomeHash before the deadline. **A nonzero hash does not prove gameplay. Acceptance is not a guaranteed payout.** The backend separately verifies the actual canonical F11 outcome and original terms before recognizing an allocation.

Allocation creates an irrevocable original-payee entitlement. Only that payee settles, directly to its immutable wallet; no post-allocation funder recovery exists even after deadline/death. Unallocated funded/accepted deposits recover only after deadline and only to the original funder. Game heirs acquire no signing or spending rights. Missing original keys can strand their claim; no admin recovery is invented. Rejecting recipients/USDC freezes can delay settlement without changing entitlement. Incoming/outgoing exact token deltas, CEI and reentrancy guards preserve liability on failure. Unrelated/forced balances grant no withdrawal authority.

State distinctions are `Funded` (deposited reserve), `Accepted` (original payee consent), `Allocated` (original funder allocates unpaid irrevocable entitlement), `Settled` (paid), `Refunded` (unused original recovery). Full amount/state/parties persist; authoritative events distinguish every transition. No SQL or provider success flag pretends to send funds.
