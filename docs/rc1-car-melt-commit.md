# Scoped car melt COMMIT provenance

This component adds a read-only test collector around the existing native COMMIT observer. It copies actual SQL parameters and returned rows before gameplay mutates them and before the observer receives the original COMMIT acknowledgment. The actual client is carried through AsyncLocalStorage; request labels are not authority. The complete transaction witness is bounded to 1,024 queries / 8 MiB; overflow retains an explicit unsupported marker.

`createCarMeltCommitObserver({onBoundary,onAttempt,context})` has the existing observer arm/disarm/wrapQuery contract. Its boundary callback receives `(boundary, carMeltProvenance)`. Pass that witness as the optional `carMeltProvenance` argument to `reconcileWorldResources` or `reconcileCarResources`. A dedicated observer connection must bypass instrumentation. The existing observer rejects overlapping native queries; this is serial COMMIT evidence, not concurrent commit ordering.

The accepted branch is one ordinary, living, non-NPC owner, one unreserved non-limited car, no Family, no fence-network/kingpin skill, no stake or made/lock modifier, one exact native melt ledger insert, and the original wrapper's persistence. Pinned original source supplies `carMelt`; executed locked character/account reads, the complete `loadOwned` UNION, the ordered car read, DELETE parameter/row count, ledger ID/parameters and complete before/after state bind identity, yield and custody. Account modifier inputs must remain unchanged. Clock advancement within the transaction, savepoints, compound writes, multiple cars, Family/NPC/limited and modified-yield branches stay unsupported. Uninstrumented melt retains its prior unknown classification.

This is test-only transaction provenance, not a new production receipt, a player-supplied assertion, sender attestation, or a second resource authority. Retained witnesses require the collector/source/artifact custody chain. Runtime files are unchanged; five LF-normalized source hashes fail closed when their reviewed implementation changes. The shared observer change only forwards an optional argument, with no snapshot sorting, readset or Family classifier change.

Run focused controls with `node test/rc1-car-melt-provenance.js`. For a native proof, provide a fresh restricted `RC1_CAR_MELT_OUTPUT` and local `COORDINATION_TEST_DATABASE_URL`, then run `node test/rc1-car-melt-provenance-postgres.js --postgres` from a clean committed checkout. The proof creates/drops its owned database and retains all failures. Two ordinary guest/character entrants use no gameplay fixtures; one acquires two distinct-yield non-limited cars by canonical boosts during initialization. Every setup attempt/outcome is retained, and original GTA cooldown plus 60 seconds elapses through the shared application/SQL clock between attempts (maximum 24). Measured actions cover wrong-owner denial, two distinct-yield melts, cached retry and already-removed denial. Every measured native committed/autocommitted/rolled-back boundary retains full resource snapshots, transaction provenance and reconciliation; full canonical snapshots and invariants bracket the workload. Counterfactual corruptions of retained native evidence never mutate the database.

No worker is imported. Setup clock advancement exercises demand-driven accrual only; measured melts remain at one instant. Worker integration, skill/ladder/Family compounds, acquisition/boost identity, full resources, 25-actor/90-day/matrix and production remain unqualified. The first native attempt at source `2683ebbc` failed baseline car conservation (+2) because its declared raw car fixtures had no canonical acquisition audit (TOOL49). It ran zero measured boundaries, retained full failed baseline, and cleaned up. The revised proof removes those fixtures rather than fabricating source receipts or waiving invariants. Two earlier source-byte preflight failures and two pre-native development failures are also retained privately. Source `ed349b5b` completed two exact melts and full invariants but failed postseal history verification (TOOL50): a test metadata spread replaced the recorder's reserved sequence with a query sequence. Its launcher exit is 1 and provisional sealed PASS is invalidated. Nesting native query metadata fixes the test without changing gameplay or weakening verification.
