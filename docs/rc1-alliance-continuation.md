# Bounded alliance process continuation

The native runner accepts a 25-actor `coordinated_alliance` observation with 24 or 48 logical hours. At hour 24, after every callback due at that boundary, it selects the first authorized conclusion action and seals an actual PostgreSQL dump, full canonical snapshot, RNG tape, original account/session identities and adapter/component cursor. The request is selected but has never been dispatched. Only the three initial founder respect fixtures precede the original measured baseline.

For a 48-hour observation the same process then executes the pending request and continues. A fresh process with `--resume=<sealed observation> --hours=24` restores that exact hour-24 checkpoint, builds the ordinary application, runs **all original startup callbacks again**, executes the exact pending request, completes remaining contributor and all-25 daily sessions, and advances the original timers through hour 48. `--compare-uninterrupted=<observation>` retains every canonical table/row/sequence difference. Real startup effects are never removed to manufacture equality. Another fresh continuation uses the same `--resume`, `--compare-uninterrupted` and `--replay=<continued observation>`; existing full actor/state/resource replay checks must all pass.

Every run requires `--postgres`, a fresh restricted `--output`, the explicit local `COORDINATION_TEST_DATABASE_URL`, `RC1_PG_BIN`, `--population=25 --seed=rc1-alpha --policy=coordinated_alliance --observe-resources`, and the same declared operational guardrails. Exact clean source bytes, configuration, parent dump/artifact hashes, RNG/policy checksums and quiescent pending state are checked before enrollment or gameplay. Completed player actions are not repeated. Unknown completed responses, outstanding HTTP hooks, in-flight invocations and ambiguous dispatched requests remain fail-closed. Mid-request crash recovery is not claimed.

The parent resource stream has a separately verifiable prefix at the checkpoint. Continuation has its own complete stream, including real startup callbacks. These are joined by exact restored canonical/resource state and explicit parent hashes, not by pretending physical setup and resumed history equal an uninterrupted stream. Application bootstrap is a separate full aggregate comparison: original `makeDb` updates canonical `schema_meta.applied_at`, which is retained in both snapshots and differences. A bootstrap mutation to another table, another schema identity field, or any sequence fails. Per-commit schema/migration coverage is not claimed. Full snapshots, native dumps, raw receipts, original callback trace, per-commit resource assertions and unknown classifications remain restricted evidence. Shared resource drift is a failure.

`node test/rc1-alliance-continuation.js` checks the actual adapter cursor, selected identity, duplicate prevention, wrong source/config/unfinished-state rejection and lossless state differences. `test/rc1-alliance-continuation-native-audit.js` independently verifies all retained artifact bytes and history chains, the exact resource prefix, actual native checkpoint rejection controls, repeated original startup callbacks, no repeated completed actions, all 18 continuation replay fields, and the complete uninterrupted diagnostic comparison.
