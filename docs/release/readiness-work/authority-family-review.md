# Scoped Family HTTP authority and historical receipt proof

This RC1 prerelease component reviews the eight original Family creation, joining, leaving, rank, tribute and war routes, Family chat, and the two roster mutations. Source and execution results remain bound to the native recorder's exact clean revision. It does not claim the complete Family/API surface, economic terminal coverage, physical clients or deployment qualification.

The authority is the server-authenticated account and its current living character/membership, never supplied account, Family or rank fields. Reviewed code is `src/server.js` for route dispatch, private chat and durable HTTP idempotency; `src/game.js::withCharacter/loadOwned` for character/account custody; and `src/social/gangs.js` for role, target and membership restrictions. Family joining is open under its existing rule; no request/approval rule is invented. Historical HTTP receipts are tested as unchanged acknowledgments after demotion/removal/leave, alongside fresh-key denial and complete before/after authority equality.

Methods reuse the previously read pinned Pashov access-control/concrete-trace pass (`c577eb7799c349de0acb187ba00ca98e14e436fd`), Plamen outcome/state invariants (`795962b96e254f2e423a2635fe7f8cb8ea1e6d69`) and Trail of Bits context/trust-map and false-positive discipline (`d3323cefbcf645678b8dc481de204b02ad3d02dc`). Adaptation: direct JavaScript/full-server PostgreSQL tests; no upstream orchestration, new static scanner or contract review claimed. Source searches distinguish `canCommand`'s boss/underboss gate from boss-only promotion. Cross-Family IDs, forged actor/rank payloads, second underboss, invalid boss role and changed idempotency payload receive explicit negative probes. Source inspection alone does not establish an in-flight revocation defect: overlapping requests can have a valid prior authorization order, and arbitrary concurrent revocation schedules remain outside this component.

Seven funded level-eligible living fixtures and one characterless account are declared before measurement. A future accrual timestamp isolates action denials from separately committed canonical accrual. Families, memberships, roles, posts and chat are then created through the canonical API. No workers or external providers run. One MVCC statement compares every schema table except the HTTP idempotency transport cache around each denial/replay. This is an authority proof, not a fixture conservation or sequence proof. Concurrent same-key kick, changed-body rejection, post-demotion controls, private chat isolation/join floor, revocation and reconstructed-server replay are included. Bootstrap stamp differences are retained separately; no full bootstrap equality is assumed.

Run `node test/rc1-family-authority-postgres.js --postgres` with explicit local `COORDINATION_TEST_DATABASE_URL` and a fresh restricted `RC1_FAMILY_AUTHORITY_OUTPUT`. All native assertions, failures, requests and full authority states are retained privately. Fresh integrated-source execution remains required after any merge.
