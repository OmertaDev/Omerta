# Bounded market-stress component

`createMarketPolicy({accountId,seed})` consumes verified bearer account context plus ordinary `/v1/session`, `/v1/me`, `/v1/market` and public `/v1/rules` views. It reads own cash, cargo/capacity and status; public listing identity, quantity, price, district and expiry; and retained own posting receipts. Other actors' inventory, hidden auction bids/reserves and database observer rows never enter selection.

Call `choose(view,{logicalAt,phase})` with a recorded `post`, `take`, `cancel`, `claim` or default `mixed` phase. The component seeds the ordering of publicly plausible candidates within that declared workload phase. Posting favors owned goods, then the cheapest public catalog reference good for a buy order; one unit uses the public minimum ask and original one-hour TTL. Taking supports fixed-price goods and order filling. Cancellation supports own live goods/orders. Claims require a retained own order receipt and a current public reduction in wanted quantity beyond already recorded claims. The canonical API revalidates everything: the 100-row public board cannot prove complete global availability or ownership outside its window. Auctions, car custody and unobserved expired warehouses remain excluded.

Persist `checkpoint()` before dispatching the returned exact `request`. Call `settle({idempotencyKey,status,replayed,response})` with a verified canonical result; status is `COMPLETED` or `DENIED`. A lost response keeps the existing key. An unresolved replay cannot manufacture a fresh completion and blocks new selection; the version 2 checkpoint retains its full decision and observed receipt for caller reconciliation. Known exact replays must match retained response hashes. `restore()` checks the state checksum and counters. A pending old-character request must be reconciled before selecting on a replacement. The caller records transport-level in-flight duplicate refusals separately and retries the same identity after the original completes. Own post receipts retain the returned expiry duration and selection time separately; delayed dispatch cannot establish an absolute deadline from selection time.

`node test/rc1-market-policy.js` checks public gates, source-only identities, warehouse custody, replay and restart. The native exercise requires explicit loopback `COORDINATION_TEST_DATABASE_URL`, a fresh restricted `RC1_MARKET_OUTPUT`, and `node test/rc1-market-native.js --postgres` from a clean committed checkout.

The native plan uses three ordinary guest/character entrants and one ordinary gin purchase funded by default starting cash. No balance, item, progression, status or deadline fixtures are used. Two takers plus an exact duplicate compete for one actual sale. One buyer must receive the only unit; the loser retains cash. The acquired unit then fills an actual buy order and is claimed by its owner. Separate goods cancellation, cash cancellation/refund and the original one-hour order expiry are exercised; a second original hourly sweep must not repeat the refund. Full canonical snapshots, per-owner cash parity, exact goods/custody counts and all canonical invariants are retained.

The shared application/SQL clock executes every due original local worker callback. SQL dispatch and native acknowledgments carry request context, client identity and local transaction identity without serializing competing writers. These are observed dispatch/acknowledgment orders, **not PostgreSQL total commit order**. Resource snapshots surround the quiescent concurrent group; they do not claim isolated per-commit attribution for overlapping transactions. Unknown resource classifications retain restricted diagnostics. Population spawning and unconfigured external integrations are excluded.

This is a bounded three-request component exercise, not the required 100-inflight burst, 12-hour soak, all market branches, full resource taxonomy, 90-day workload or 225-run matrix qualification. Earlier workload evidence and failures remain frozen at their own source revisions.
