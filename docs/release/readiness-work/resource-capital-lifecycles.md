# Original operation capital lifecycle proof

Run `node test/rc1-capital-lifecycle-journal.js`, then from a clean committed checkout with an explicit local PostgreSQL administrative endpoint in `RC1_RESOURCE_DATABASE_URL`:

```
node test/rc1-native-capital-lifecycles.js --postgres
```

The runner retains a unique database and a new private temporary evidence directory. `--seed=VALUE` selects the recorded deterministic stream and `--output=PATH` selects a new external private directory. Source hashes and clean status are checked before execution and at sealing; installed dependencies are the shared local runtime and are not independently attested.

The unchanged `COORDINATION_OPERATION_PILOT` retains its original 86400-second lifetime, catalog identity, requirements and compiled definition. Shared native application/SQL clocks execute every original local worker callback through hour24. No operation expiry worker exists: after checking that capital is still held at the unchanged deadline, the canonical `expire` command performs recovery. Equality is permitted; one millisecond earlier is refused. This is original-duration logical-clock proof, not literal 24-hour wall-time or deployed timing equivalence.

Four schema-default player characters start with500 cash and25 ammunition each. Their initial zero-resource Family and four-member crew are explicit social fixtures. No extra cash, materials, progression or knowledge is granted. Population activity is disabled by its normal deployment flag. The boss dies through canonical estate processing, not a combat-earned death. No post-baseline balances, statuses, deadlines or outcomes are rewritten.

The proof deposits100 per operation and checks living withdrawal and cancellation refunds, replacement withdrawal and cancellation forfeits, two original24h expiry refunds and two original24h expiry forfeits. Original capital stays bound to the dead depositor and never reaches the replacement. Each terminal group injects a late transaction-receipt failure, proves full authoritative rollback, retries with the same key, and replays without movement. Deposit rollback, stale-character refusal and exact replay from a new pool/service are included. A new pool is not a process crash/restart proof.

Every observed command and worker advance retains complete restricted before/after rows, result, immutable receipts and exact equations for personal resources, each capital obligation, and total personal-plus-held cash. The pure verifier rejects wrong original owners, missing or repeated receipts, early expiry, rewritten deadlines, lost material custody and unexplained fractional cash. Original workers are observed as aggregate advances, not individual commits. Full canonical invariants must pass without subtracting fixture drift. Failures remain retained.

The earlier60s definition-fixture material/spend proof remains separate. This runner does not re-execute that branch or prove HTTP authentication, Player Command dispatch, natural entry, concurrent scheduling, unshielded combat, process recovery, deployment, the full simulation matrix, or other resource categories. Those requirements remain OPEN.
