## Source boundaries

Neither already brands the ordinary G estate client.

Passing a proxy pool that returns the G client to withItemTransaction would issue/commit a second boundary and is not an acceptable bridge.

Existing global reducer transferred (invariants.js 1118) and escrowed (1126) both require active source state. They cannot truthfully encode an already-escrowed operation relay.
- Mystery ownership predicate line 1215 and selectOwnedItem line 1441 see only personally active tools. applyEffects line 1515 escrows the selected tool; completeGraphNode line 1593 sets the completed node then calls real F05 wear before saving its result. releaseMysteryEscrow line 1452 refuses any depositor other than the Mystery root owner.

- Rental toolAuthority locks the active lease before item and custody, checks the original borrower and lease/Mystery operation identity, then reads the database clock. recoverEquipmentRentalsAtDeath requires Items branding and a dead original actor; its finish currently expects custody in the lease operation.

## Minimal implementation sequence for the coordinator

1. Add a caller-owned Items callback boundary that validates an already-active caller transaction, enters the existing registry/global item gate and private Items ALS brand, and exits without BEGIN/COMMIT/release. It must propagate caught-leaf poison and register rollback compensation with the actual outer owner. The G wrapper must enter this boundary before its first character lock and keep it around the entire death-capable action; a small pre-lock callback alone is insufficient. Native rollback remains the outer canonical transaction. No raw-client shape or forged marker may grant the brand.
2. Before any character lock, read bounded equipmentRentalDeathCounterparts for the possible death subjects, form the finite sorted actor set with the primary pair, and acquire it in one consistent order. Re-read rental counterparts after locks; if a new counterpart appeared, abort/retry the whole transaction instead of acquiring a lower actor late. Lease acceptance locks the involved actors, so the recheck closes the discovery race. Actual mod/combat/hired-gun/bounty/pen estate callers must all use the same preparation. Preserve NPC/no-rental death behavior.
3. Add relayEscrowCustody(client,{fromOperation,toOperation,itemId,reason},mutation) as a private-root-only canonical leaf. Require both operation IDs in trusted server-created root authority, distinct IDs, current item operation/state and the same custody row. Update item owner_id and custody.operation_id conditionally; preserve depositor_scope/depositor_id, physical UID, state, creation quality and certificate. Append a distinct truthful escrow_relayed event from operation to operation. Extend the literal event-kind CHECK and global reducer for exactly this transition, retaining every old negative. Do not release to a borrower or allow a standalone string-key relay root.
4. Add a closed Belladonna/version1 precision-tool availability path for both the ownership predicate and effect selection. Read-only boards need a read variant; the existing branded rentalToolAuthority cannot be invoked from an unbranded read. Selection must discover/lock rental rows before physical item locks and validate original borrower, live lease, actual custody, instance and template. Keep ordinary owned-tool behavior unchanged; never extend borrowed authority to item_consume, trade, grants or generic templates. Include the lease operation in the server-derived Mystery root authority only for this path.
5. Relay lease→Mystery, complete the real tumbler interaction, and record wear from the actual relay event. The rental wear branch must independently bind original borrower/account, lease ID, source/destination operations, root request key, completed Belladonna node and original landlord depositor. Recheck database expiry after waits. Keep the ordinary F05 person-origin branch unchanged. No cancellation, reservation, replay or mere availability check may create wear.
6. Prefer relay back to the lease immediately after completed lock-node wear, before saving the node result, because the tool is needed for that finite action. This avoids parking a borrowed tool until the whole investigation terminates. If authored semantics require holding it longer, all terminal/cancel/death paths must instead return it via a release-only rental recovery branch. That recovery ignores eligibility/expiry only to restore the recorded lease operation; it cannot authorize another use. Return must preserve landlord title even when a lease expired or an original party died. After relay back, ordinary rental end releases only to the original landlord account.
7. After the canonical estate dead-character UPDATE and before heir insertion, invoke branded rental cleanup under the already-held finite actor locks. If custody is still in a bound Mystery, relay it back before finish. Refund only the living original borrower; burn a dead original borrower's deposit; preserve original landlord-account physical title. A source-approved cancellation/recovery may require historical graph metadata but must not execute fresh nodes or fabricate a new person owner.
8. Preserve canonical in-memory actor cash discipline: rental cash() updates a freshly queried actor object. If the living borrower receiving a death refund is the G acting character/killer, G.persistCharacter can overwrite that SQL refund with its older cash. Merge the exact verified rental refund delta into the original in-memory G actor, as estate already does for other escrow refunds. Do not reload SQL cash and erase loot already accumulated in memory. Other prelocked counterparts not persisted by G may retain direct canonical SQL updates.
9. Add rental deposit bucket/known journals, literal schema catalog and named full-state custody/deposit/condition checks, then qualify the actual frozen union. The rental oracle's current 1001-row window reports check_limit for legitimate larger worlds; it needs complete coverage or an explicitly separate incomplete-proof result, not a conservation failure or a green partial scan.

## Required frozen-source proofs

Actual registered JWT lease offer/accept plus real Belladonna discovery/tumbler completion must produce landlord-owned physical UID custody lease→Mystery→lease, exactly one wear debit, and return to the landlord without borrower disposal authority. Exercise owned-tool parity, ordinary/tempered birth condition, expired source after a held lock, wrong borrower/instance/operation, forged relay/private token, replay, cancel with no fabricated wear, return while held, and caught-leaf/late failure rollback. Run independent global item provenance, condition, rental deposit and cash books.

Native estate proofs must call actual runEstate through canonical wrappers: borrower death, landlord death with a living borrower, borrower-as-killer refund persistence, NPC/no-leases, duplicate death, cross-estate/rental/use contention and rollback. A post-commit rental cleanup or manual helper followed by an heir fixture does not establish atomic estate integration. Test counterpart discovery changes cause whole-action retry, sorted lease→item locks, no heir deposit windfall and unchanged physical creation/certificate. Existing private fixtures may remain as leaf controls but must be labeled separately.

This bounded design applies the policy's pinned authority/replay, state/accounting and specification/invariant passes. It does not claim executed new native proofs, release clearance, deployed behavior or a broader audit. Financial activation, paid compute and external owner spending authority remain off.
