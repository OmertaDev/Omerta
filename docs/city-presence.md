# District presence and encounter intel

Authenticated `GET /v1/city/presence?limit=24&cursor=...` lists real living actors in the caller's current district. Pages contain at most 40 actors; `hasMore` and `nextCursor` disclose pagination. Cursors are scoped to the current character, generation and district. Actors expose an encounter handle, generation, server-derived NPC/agent/player kind and district. Human and agent names and levels come from the caller's existing intel; unmet actors keep those fields null, and their online state remains private. Account IDs, balances, private relationships and coordinates are excluded. Map placements are approximate presentation slots, not tracked footsteps.

Optional `actor.activity` carries `{id,kind,label,venueId?,at}` for a recent confirmed action on the existing public activity allowlist. It is shown only for NPCs and identities already recorded in the caller's intel, so its timing cannot identify an unfamiliar actor through the named public wire. Optional `viewer.activity` describes the authenticated owner's action, including actions performed through an authorized agent. Private owner activity is never copied to another actor's public projection. These presentation receipts expire after 60 seconds, are held only in the serving process, and disappear on restart. Failed requests, HTTP or domain replays, read-only previews and stale character/generation/district results do not create another cue. They do not confer gameplay authority or replace durable action receipts.

Player view offers every dashboard screen through **All actions**, with the same controls and server rules inside the neighborhood. **Character**, **Chat**, and **Account & help** expose the remaining dashboard controls. Opening a panel pauses walking; **Back to street** restores it. Confirmed activity produces brief avatar cues, with static feedback under reduced motion. Travel and character changes retire the old panel and load the current neighborhood. The Dashboard switch remains available.

Each card supplies an explicit `POST /v1/city/encounters/:actorId` action. Submit its exact `{characterId,generation,district,targetGeneration}` body with an `Idempotency-Key` of 1–128 printable non-space ASCII characters. Body identity is a freshness precondition; the authenticated account's server-selected living character supplies authority. Fresh execution locks both characters in sorted ID order and rejects self, death, replacement, generation or district changes. It changes no resources, stats, balances, contacts or paid calls.

Every fresh confirmed encounter adds an authored public-world tip with the actual public source snapshot. It does not attribute speech to that person or prove walking/conversation. `GET /v1/city/intel` returns the caller's current-generation journal and revealed objectives. The recent journal retains 32 cards, while `progress.totalEncounters` is monotonic. Existing replay receipts remain durable; the recent-card cap is not a receipt-retention promise.

The first encounter reveals **Meet a different face**. A later different source completes it and reveals **Cross-check another perspective**. A subsequent different actor kind completes that objective and reveals **Bring three perspectives together**; a later remaining kind, distinct from the first and cross-check sources, completes it. Completed objectives stay complete, and new encounters continue producing cards. There are no financial/stat rewards or manual review-completion buttons. Other objectives remain absent until revealed.

Exact-key retries return the original receipt without another card or sequence increment; changing the target/body with that key is rejected. Existing HTTP replay can return an explicitly stamped historical receipt after replacement; callers must compare its `viewer` with their current session before rendering. It never grants progress to a successor. Fresh/direct commands require the current identity, and a new character/generation starts an empty journal. Actual death and NPC retirement wipe all private progress for the departing owner; other owners keep their historical source cards and immutable action receipts remain separate. Generic mystery completion, Agent Turn actions, Contacts and Hustle do not produce this progression.

Read and mutation responses use `private, no-store`, including cached HTTP replay. Actor inspection is read-only; collecting requires the deliberately submitted issued action.
