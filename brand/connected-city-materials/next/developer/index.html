OMERTÀ / DEVELOPER QUICKSTART

From request to result.

Run real Omertà handlers with synthetic accounts. Salvage a wreck, craft hardened steel, then complete a shared investigation.

Local repository example. In-memory database. No production token or wallet required.

Watch the first three steps.

Reused narration and footage from our verified walkthrough. Read transcript · Watch the complete investigation

1. Run the fixture.

Use an existing local Omertà checkout with its root dependencies installed and Node.js available. From the repository root:

node brand/connected-city-materials/next/developer/run-demo.mjs

The script rejects a configured DATABASE_URL or production NODE_ENV. It enables Coordination only within its process, creates three synthetic accounts in memory, calls the actual handlers, asserts outcomes and writes a local result file. It does not start a public server. Run it from a development shell without production configuration.

The observed salvage returns 6 scrap steel, 2 wire and 2 salvage parts. Crafting consumes 4 scrap steel and 300 game cash, creating 1 hardened steel.

3. Follow the evidence.

Read the Coordination catalog and use its current content hash to create the Split Ledger instance. Follow server-issued actions with the expected revision. Discover the Docks and Foundry sources under different accounts, resolve the sharing recipient, share, and read the instance again.

GET  /v1/coordination
POST /v1/coordination/{graphId}/instances
     { expectedContentHash }
POST /v1/coordination/instances/{instanceId}/act
     { expectedRevision, actionId }
GET  /v1/coordination/knowledge
GET  /v1/coordination/knowledge/targets?characterName=Demo%20Archivist
POST /v1/coordination/knowledge/{claimId}/share
     { targetId, expectedAclRevision }

POST requests use idempotency keys. Reuse a key only to retry the same logical operation with the same payload. The example generates a new key for each distinct operation. Do not hardcode action IDs or reuse stale revisions.

Expected outcome

24 successful local responses
hardened steel: 1
remaining scrap steel: 2
game cash: 9700
Split Ledger: completed

Success is evidence for this local fixture. Public rollout, account eligibility and other environments can differ.

If something fails

Missing package errors mean the root repository dependencies are not installed. The safety guard means the shell has production database configuration. Assertion failures mean the current checkout differs from the documented flow; inspect the failing response instead of weakening the assertions.
