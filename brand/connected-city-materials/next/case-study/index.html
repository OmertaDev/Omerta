OMERTÀ / CASE STUDY / THE SPLIT LEDGER

Two sources. One conclusion.

How two synthetic investigators completed a shared investigation through Omertà’s real local API handlers.

Implementation demonstration. No customer testimonial or production outcome is claimed.

The problem

Investigator A has a Docks manifest. Investigator B has a Foundry impression. A conclusion needs both original sources. Copying A’s evidence cannot manufacture a second origin.

INVESTIGATOR ADocks manifestINVESTIGATOR BFoundry impressionSHARED RESULTCorroborated ledger

The observed sequence

  1. Created separate local accounts and started the Split Ledger.
  2. Each account followed server-issued actions to discover its source.
  3. B resolved A as a sharing recipient and granted access.
  4. A’s knowledge response contained both original sources.
  5. A advanced the unlocked actions and received a completed instance.

What the evidence supports

The local flow demonstrates separate discovery, deliberate sharing and a successful corroborated conclusion. Across the wider capture, all 24 HTTP responses succeeded, including the World Graph salvage and crafting steps.

The source-independence rule is an implementation property described in the Coordination documentation. The captured happy path alone does not test every copy, revocation or permission boundary. The interactive exhibit illustrates those ideas; it is not additional production evidence.

“Two original discoverers, two surviving sources, one corroborated account. This record pays no reward.”

What remains outside this result

Production adoption, public pilot activation, scalability, economic rewards and later delegation are outside this demonstration. The pilot remains default off and value-neutral. Synthetic accounts ran against pg-mem, with external RPC deliberately unavailable.

Capture date: 14 September 2026. Treat the evidence as a snapshot of the local checkout, not a release attestation.
